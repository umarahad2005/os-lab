What is a Process?
A process is a program in execution.

What is PCB (Process Control Block)?

 2. Conceptual Understanding

 What is Scheduling?
Scheduling is the process of selecting a process from the ready queue and allocating
CPU to it.

 OS decides:
"Which process should run next?"

 Why Scheduling is Important?
     Efficient CPU usage
     Fairness among processes
     Reduced waiting time
     Improved performance

5. Scheduling Algorithms to Implement

5.1 First Come First Serve (FCFS)

Logic

    First process in queue executes first
    Non-preemptive

Execution Flow

Ready Queue: P1  P2  P3
Execution:
P1  P2  P3

Implementation Idea

PCB p = readyQueue.poll();
runningProcess = p;
p.state = "Running";

14 | P a g e
Sample Output
Time Process
0­4 P1
4­7 P2
7­10 P3

 5.2 Round Robin (RR)

Logic

     Each process gets fixed time quantum
     Preemptive scheduling

Example

Time Quantum = 2

P1(5), P2(3), P3(2)
Execution:
P1  P2  P3  P1  P2  P1

Implementation Idea

int timeQuantum = 2;
while (!readyQueue.isEmpty()) {

       PCB p = readyQueue.poll();
       p.state = "Running";
       int execTime = Math.min(timeQuantum, p.remainingTime);
       p.remainingTime -= execTime;
       if (p.remainingTime > 0) {

              p.state = "Ready";
              readyQueue.add(p);
       } else {
              p.state = "Terminated";
       }
}

9. Page Replacement (LRU Algorithm)
 What is LRU?
Least Recently Used page is replaced first.

Example
Memory size = 3
Reference String:

P1  P2  P3  P1  P4

Step-by-Step

Step  Memory      Action
P1    P1 _ _    Load
P2    P1 P2 _   Load
P3    P1 P2 P3  Load
P1    P1 P2 P3  Hit
P4    P1 P4 P3  Replace P2

LRU Diagram

Before:
[ P1 ][ P2 ][ P3 ]

After P4:
[ P1 ][ P4 ][ P3 ]

             replaced (least recently used)

10. LRU Implementation Idea

List<Integer> memory = new ArrayList<>();
Map<Integer, Integer> lastUsed = new HashMap<>();
int time = 0;

for (int page : referenceString) {
       time++;

       if (!memory.contains(page)) {
              if (memory.size() < capacity) {
                     memory.add(page);
              } else {
                     int lru = Collections.min(lastUsed.entrySet(),
                             Map.Entry.comparingByValue()).getKey();

22 | P a g e
                     memory.remove((Integer) lru);
                     memory.add(page);
              }
       }
       lastUsed.put(page, time);
}

 1. Objective of This Module
In this module, you will simulate how processes:

     Share resources safely
     Avoid conflicts (race conditions)
     Communicate with each other
 This is the final logical layer of your OS simulation.

 2. Conceptual Understanding

 What is Process Synchronization?
Synchronization ensures:
Multiple processes do NOT access shared resources at the same time in a conflicting
way.

 What is a Critical Section?
A critical section is a part of code where:

     Shared resource is accessed

 Problem: Race Condition
Occurs when:
Two processes access shared resource simultaneously  incorrect results

3. Race Condition (Diagram)

Process P1              Process P2
                              

Read Data            Read Data
Modify               Modify

Write                Write  Conflict

4. Solution: Mutual Exclusion
Only one process can enter critical section at a time.

5. Synchronization Mechanisms
You must implement ONE of the following (recommended: Semaphore)

 5.1 Semaphores (Recommended)

What is Semaphore?
A semaphore is a variable used to:

     Control access to shared resource

Types:                      Description
                     0 or 1 (Lock/Unlock)
          Type       Multiple resource access
Binary Semaphore
Counting Semaphore

Working (Diagram)

Semaphore = 1

P1 enters  Semaphore = 0
P2 tries  Blocked 
P1 exits  Semaphore = 1
P2 enters

Implementation Idea

class Semaphore {

26 | P a g e
       int value = 1;
       synchronized void waitSem() {

              while (value == 0) {
                     try { wait(); } catch (Exception e) {}

              }
              value--;
       }
       synchronized void signalSem() {
              value++;
              notify();
       }
}
